# v4 Conformance Checklist

Every LOCKED decision in `GDD_Master.docx` (v4.0), as something a machine can
check. `tools/gdd_audit.gd` parses this file and reports what is built, what is
missing, and what only a human can judge.

**This file is machine-read.** Keep the table format intact.

---

## Why this exists

The v4 delta is not a patch. It is nine new enemies, three new buildings,
twenty-four hero nodes, four currencies, a new world, a new final boss, and
three systems that do not exist yet — against a build that currently ships and
works. Over a migration that size, "how far along are we" stops being answerable
by looking, and "done" starts getting reported before it is true.

So the GDD becomes a burndown. Run the audit, get a number.

---

## How a probe works

The `Probe` column is executed against the project. Everything else is prose for
humans.

| Probe | Meaning |
|-------|---------|
| `count:<dir> >= <n>` | at least `n` `.tres` files in `res://data/<dir>/` |
| `count:<dir> == <n>` | exactly `n` |
| `class:<Name>` | a script declares `class_name Name` |
| `const:<NAME>` | `Balance` declares that constant |
| `signal:<name>` | `EventBus` declares that signal |
| `file:<res path>` | that file exists |
| `method:<Class>.<name>` | that script declares `func name` |
| `manual` | needs a human. Always reported separately, never counted as done. |

A probe is a *smoke test*, not proof. `count:enemies >= 18` says eighteen files
exist; it cannot say they are good enemies. Passing the audit is the floor, not
the goal — §52's acceptance checklist and the kill questions are the ceiling.

## 8. Release requirements — GDD §52

These are the ones that get skipped because nothing breaks when they are missing.

| Item | Target | Probe |
|------|--------|-------|

| Key rebinding | all actions | `class:KeyBindings` |

| Controller parity | every screen focusable | `manual` |

| Night playable at minimum brightness | readability under load | `manual` |
